## 2주차 과제2 - 시나리오별 최적 자료구조 매핑 리포트

### 1. 상품 코드를 입력하면 즉시 재고 수량을 확인해야 하는 재고 관리 데이터
- 사전(dict) 자료형이 적합하다.
    - 상품 코드와 재고 수량은 'key-value' 관계이므로, 상품 코드를 키로, 재고 수량을 값으로 저장하는 사전 자료형이 적절하다.
    - 파이썬 사전은 해시 기반으로 동작하므로, 상품 코드를 이용한 값 조회가 빠르고 효율적이다.

- 리스트와 튜플은 인덱스를 통한 접근에는 유리하지만, 상품 코드를 이용해 원하는 재고 수량을 찾으려면 일반적으로 순차 탐색이 필요하여 O(n)이 걸린다. 또한 튜플의 경우 재고 수량을 수정할 수 없다.
- 집합은 원소 존재 여부를 빠르게 확인할 수는 있으나, 상품 코드로 재고 수량을 확인하는 구조를 구현하기에는 적절하지 않다.

```python
stock = {"A-1000":3, "A-1010":2, "B-1800":10}
code = input("상품 코드: ")
print("재고 수량:", stock[code])
```

### 2. 이벤트 응모 고객 명단에서 중복 응모를 제거하고, 기존 회원 명단과의 교집합을 구해야 하는 상황
- 집합(set) 자료형이 적합하다.
    - 파이썬 집합은 중복을 허용하지 않으므로, 명단에 고객이 중복되어 입력되는 것을 막을 수 있다.
    - 파이썬 집합 연산자나 메소드는 기존 회원 명단과의 교집합을 쉽게 구할 수 있게 해 준다.

- 리스트와 튜플은 원소의 중복을 허용하므로 중복 제거를 별도로 처리해야 하며, 교집합을 구할 때도 추가적인 탐색 과정이 필요하므로 번거롭다.
- 해당 데이터를 사전 자료형으로 관리하고자 한다면 고객마다 고유한 연락처를 키로 설정하고 값으로는 응모 여부에 따라 0 또는 1 값을 둘 수 있겠으나, 기존 회원 명단과의 교집합을 구하는 과정이 번거롭다.

```python
members = [
    {"name": "John Doe", "phone": "010-0000-0000"},
    {"name": "Jane Roe", "phone": "010-1111-1111"},
    {"name": "John Smith", "phone": "010-2222-2222"},
    {"name": "Jane Smith", "phone": "010-3333-3333"}
]
entries = {
    "010-0000-0000",
    "010-1234-1234",
    "010-1111-1111",
    "010-3456-3456",
    "010-7890-7890",
}
member_entries = entries.intersection([member["phone"] for member in members])
print("응모 고객 중 기존 회원:", member_entries)
```

### 3. 월별 매출액을 1월부터 12월까지 순서대로 저장하고 순회하는 데이터
- 리스트(list) 자료형이 적합하다.
    - 1월부터 12월까지의 매출액을 순서대로 저장하고 순회해야 하므로, 순서를 유지하면서 인덱스로 접근할 수 있는 list가 적합하다.

- 사전을 이용하여 월을 키로 별도로 관리하기보다는, 정해진 순서대로 값을 저장하는 것이 단순해 보인다.
- 집합은 순서를 기준으로 데이터를 저장하거나 인덱싱할 수 없으므로 적합하지 않다.
- 튜플은 리스트와 마찬가지로 인덱싱을 이용한 접근이 가능하나, 월별 매출액은 변경될 가능성이 있으므로 수정 가능한 리스트를 선택하였다.

```python
sales = [10000, 11000, 12000, 13000, 14000, 15000, 16000, 17000, 18000, 19000, 20000, 21000]
for i in range(12):
    print(f"{i+1}월 매출액: {sales[i]}")
```

### 5. 1,000만 줄짜리 웹 서버 접속 로그 파일에서 특정 조건의 줄 수를 세는 작업
- Generator를 활용한 순차 처리
- 리스트, 집합, 사전 등의 자료구조에 전체 로그를 저장하면 1000만 줄의 데이터를 모두 메모리에 유지해야 하므로 많은 메모리가 필요하다.
- 따라서 전체 로그를 메모리에 적재하는 것이 아니라, 파일을 한 줄씩 순차적으로 읽으면서 조건을 확인하는 방식이 메모리 효율적이다.

```python
def read_log(path):
    with open(path, encoding="utf-8") as f:
        for line in f:
            yield is_exist

total = sum("GET" in line for line in read_log("web_logs.csv"))
```
